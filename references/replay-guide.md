# 复现与校验指南

复现阶段的目标不是「尽量做完」，而是**让每一步都可核对、可停下、可回退**。**进入复现前必读。**

## 1. 开跑前确认清单（确认节点 2）

逐项向用户确认，任一未确认都不得开始写操作：

1. 目标软件／工程／项目文件的绝对路径，以及当前是否已打开、是否有未保存内容。
2. 输入素材绝对路径、输出目录、成片命名规则。
3. 是否允许真实点击、真实写文件、覆盖同名文件（默认**不允许覆盖**）。
4. 危险操作白名单：删除、清空时间线、覆盖原素材、发布上传、支付、发送消息，默认全部禁止。
5. 遇到失败时是否自动继续（默认**暂停等待用户选择**）。
6. `variables` 中每个 `required: true` 的具体取值。
7. 档案中所有 `low` / `unverified` 项是否已由用户确认。

涉及账号登录、付费功能、云端渲染时，先确认用户已自行完成登录/授权，不代管凭据。

## 2. 通道选择

| 条件 | 通道 | 说明 |
|---|---|---|
| 目标软件在本机、有桌面/浏览器控制能力 | A · GUI 复现 | 逐步操作 + 逐步截图，最贴近教程原意 |
| 步骤本质是文件批处理、ffmpeg、软件 CLI/API | B · 可脚本化 | 先 dry-run，再执行；可复现性与速度最好 |
| 无桌面控制能力，或用户只想自己动手 | C · 指令清单 | 输出逐步指令与期望界面，用户执行后回报 |

同一个案例可以混用：例如素材预处理走通道 B，软件内调参走通道 A。混用时在 `replay-log.json` 的每步写 `channel` 字段。

### 通道 A · GUI 要点

- 只加载 `replay-card.md`，按 `step_id` 顺序执行；需要证据时再打开完整档案或关键帧。
- 每步执行前先确认 `precondition_state`：界面不符就暂停，不要硬点。
- 每步执行后截图存 `runs/<日期>-<目标>/shots/<step_id>.png`，与档案 `evidence[].frame` 对照；**界面状态判断由 Agent 看图完成**，不以命令返回码代替。
- 涉及异步处理（AI 识别、渲染、上传）时按 `wait` 步骤轮询状态，设置明确的等待上限，超时标 `failed` 并暂停。
- 快捷键仅在档案明确记录时使用；不同版本/输入法的快捷键可能不同，失败时改用菜单路径。
- 遇到弹窗、登录态失效、版本差异导致控件找不到，立即标 `failed` 并请求人工接管，不尝试猜测相似按钮。

### 通道 B · 可脚本化要点

- 脚本先以 dry-run 模式打印完整命令、输入路径、输出路径与预计影响的文件数，交用户确认。
- 输出到新目录，不原地覆盖；需要覆盖时单独确认。
- 命令中的路径全部来自 `variables`，不硬编码教程里的路径。
- 执行后核对产物数量、大小、时长与 `expected`；仅「命令退出码为 0」不算验收通过。

### 通道 C · 指令清单要点

- 每条指令写清：在哪个界面、找哪个控件、填什么值、做完应看到什么。
- 附上对应档案关键帧路径，便于用户对照。
- 用户回报后再把结果补进 `replay-log.json`，不能凭空标记为 `ok`。

## 3. replay-log.json 格式

```json
{
  "case_id": "jianying-ai-subtitle",
  "run_id": "2026-11-12-newclip",
  "target": "D:/素材/newclip.mp4",
  "variables_used": {"INPUT_VIDEO": "D:/素材/newclip.mp4", "OUTPUT_DIR": "D:/成片/"},
  "steps": [
    {"step_id": "S01", "channel": "A", "status": "ok",
     "observed": "素材出现在媒体库，缩略图可见", "screenshot": "shots/S01.png"},
    {"step_id": "S02", "channel": "A", "status": "deviation",
     "observed": "转场时长设为 0.3s，教程为 0.5s", "screenshot": "shots/S02.png",
     "note": "按新素材节奏主动调整，已在确认节点 2 报备"},
    {"step_id": "S03", "channel": "A", "status": "failed",
     "observed": "导出按钮灰色不可点", "screenshot": "shots/S03.png",
     "note": "疑似当前账号未开通该导出规格"}
  ]
}
```

`status` 只允许 `ok` / `deviation` / `failed` / `skipped`：

- `ok`：截图/文件状态与 `expected` 一致。
- `deviation`：完成了但参数或结果有意偏离，必须在 `note` 写明原因与是否报备。
- `failed`：未完成，必须暂停。
- `skipped`：经用户同意跳过。

**每步立即写入**，不要等全部跑完再补写，避免中断后丢失记录。

## 4. 失败处理

任一步 `failed` 时立即停止，向用户给出三个选项，不自行决定：

1. **重试** — 修正前置状态或参数后重做本步。
2. **跳过** — 明确说明跳过会影响哪些后续步骤的 `precondition_state`。
3. **人工接管** — 用户手动完成后回报实际界面状态，Agent 记录并继续。

禁止：连续盲试相似按钮、自动降低参数要求凑结果、把 `failed` 改写成 `deviation` 美化完成率。

## 5. 校验

```
python "{SKILL_DIR}/scripts/run.py" verify --steps "{CASE_DIR}/steps.json" --log "{RUN_DIR}/replay-log.json"
```

产物 `verification.json` 含 `summary`（总步骤、必做步骤、必做完成率、各状态计数）与 `pending_actions`。

解读规则：

- `similarity_hint` 只是 `expected` 与 `observed` 的中文二元组重合度，**不是验收结论**；数值高低都不能替代截图比对。
- `missing` 表示日志里完全没有该步骤记录，需补做或确认是否标为可选。
- `deviation` 要区分「已报备的有意调整」与「无意执行偏差」，前者可在交付说明中保留，后者需回退重做。
- `required_completion_rate` 只统计 `required: true` 的步骤；不要把可选步骤计入分母来抬高数字。
- 交付前把完成率、全部 `deviation` / `failed` / `missing` 项摆给用户确认（确认节点 3），不隐瞒。

## 6. 剪辑 / AI 软件动作映射参考

用于把画面上的控件名归到稳定的动作描述，避免因软件版本改名而复现失败。

| 画面常见表现 | 动作描述 | `expected` 示例 |
|---|---|---|
| 素材拖进左侧面板 | `gui` → 导入素材 | 媒体库出现该素材缩略图与时长 |
| 片段拖到时间线 | `gui` → 添加到轨道 | 主轨道出现片段，播放头可移动 |
| 右侧参数面板数值变化 | `input` → 修改参数 | 数值显示为指定值，预览同步变化 |
| AI 字幕 / 智能识别 / 一键成片 | `gui` + `wait` → 触发识别并等待 | 生成字幕轨道或结果列表，进度到 100% |
| 片段交界处出现图标 | `gui` → 添加转场 | 交界处显示转场标记，时长面板可读 |
| 色轮 / 滤镜 / 调色面板 | `input` → 套用预设或参数 | 预览画面变化，面板显示预设名与数值 |
| 导出对话框 | `gui` + `wait` → 设置规格并导出 | 输出目录出现文件，分辨率/码率符合设定 |
| 多片段重复同类操作 | 一步 + `loop` | 全部目标片段状态一致 |

教程里的软件若与用户当前版本界面不同，以**功能语义**对齐，不强行找同名按钮；差异写进 `replay-notes.md` 并提示用户确认。

## 7. 安全边界（硬性禁止）

- 不删除、不清空用户已有工程、时间线或素材；需要清理时让用户自己操作。
- 不覆盖同名输出文件；默认写入新目录或加时间戳后缀。
- 不代替用户点击发布、上传、分享、支付、发送消息。
- 不读取或记录账号密码、令牌、验证码；关键帧含此类信息时打码或跳过。
- 不在未确认的情况下安装软件、修改系统设置或联网下载。
- 不把用户素材上传到任何在线服务；`fetch` 只下载公开教程视频。

## 8. 交付与留痕

`runs/<日期>-<目标>/replay-notes.md` 至少写：

- 本次使用的 `variables` 取值与目标素材
- 各通道使用情况
- 完成率与逐项偏差原因
- 未复现步骤及建议的后续处理
- 软件版本差异、弹窗、授权限制等环境信息
- 档案需要修订之处（回写 `operation-profile.md` 的修订记录）
