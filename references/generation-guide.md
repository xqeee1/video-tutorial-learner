# 动作类视频与生成侧指南

适用于**分支 B**：输入视频不是软件教程（舞蹈、动作示范、运镜／表演演示），用户要的是把动作迁移到自己的角色／场景上，交付成品视频或图像。

本文件只写「从取证到生成」的可复用要点。取证参数细节见 `evidence-guide.md`，档案字段见 `operation-schema.md`，安全边界见 `replay-guide.md`。

> 文中生成侧限制来自 2026-11-12 的真实案例实测。**模型与平台能力会更新**，每次执行前先做小规模单段验证，不要把这些参数当成永久事实。

## 1. 判据

同时满足以下两条即走分支 B：

- 画面里没有软件界面／菜单／参数面板，主体是人、动物或物体的连续动作；
- 用户诉求是「复刻动作／让某角色跳这段／做一条同款视频」，而不是「学会怎么点软件」。

判不准时直接问用户，不要默认按 GUI 教程处理——两条路线的产物和成本差别很大。

## 2. 取证差异

| 项 | 分支 A 软件教程 | 分支 B 动作类 |
|---|---|---|
| `--interval` | 3 秒（菜单快切 1–2 秒） | **1 秒**，手势／转身常在 1 秒内完成 |
| `--scene` | 0.35，用于捕捉界面切换 | 固定机位可加 `--no-scenes`；`scene_frame_count=0` 属正常 |
| 转录对齐 | 口述讲解是重要证据 | 音轨多为音乐／无口述，**跳过转录**，纯画面路线并在档案注明 |
| 主要证据 | 参数面板、状态差 | 接触表建立节奏 + 单帧细看姿态 |
| 补抽密帧 | 需要时按 `evidence-guide.md` | 循环动作边界处按 `fps=4` 密抽，确认节拍起点 |

舞蹈／动作类要优先读接触表判断**循环周期**，这直接决定后面怎么切段。

## 3. 动作分段表

写进 `operation-profile.md`，并作为生成提示词与切段依据。字段：

| 字段 | 说明 |
|---|---|
| `segment_id` | `B01`、`B02`… |
| `time_range` | 原视频时间区间（秒） |
| `pose` | 主要身体姿态（站姿、顶胯、屈膝、侧倾） |
| `gesture` | 手臂／手部动作（脸侧比划、双臂上举、胸前推掌） |
| `tempo` | 循环周期，例如「约每 2 秒一组」 |
| `loop` | 是否与前段重复；重复段可掩盖拼接接缝 |
| `evidence_frame` | 对应 `frames/*.jpg` 路径 |
| `confidence` | 画面清晰可读为 high；遮挡／快切为 medium |

示例（19.85 秒单人舞蹈实测）：

| 区间 | 动作 | 循环 |
|---|---|---|
| 00:00–00:03 | 站立预备 → 双手脸侧比划 → 双臂上举过头顶 | 起势 |
| 00:04–00:11 | 手落回胸前交替推掌、指尖手势，胯部左右顶摆 | 每约 2 秒一组 |
| 00:12–00:19 | 手划向腰侧、身体侧倾、甩发，重复同组律动收尾 | 重复 + 收势 |

**不要臆造姿态数据**：看不到脚步就写「原地律动」，不要补写具体步法；看不到转身就写「无走位无转身」。

## 4. 视觉参考准备

1. **合成首帧**：角色图 + 背景图做图生图，`input_fidelity` 取高值锁人物。提示词必须明确：
   - 角色外观、服装、发饰全部保留；
   - 画风与背景统一；
   - **歧义项先问用户**：角色手持道具（剑、扇、话筒）是收起、悬浮还是保留手持——是否空出双手直接影响动作贴合度；
   - 构图留头顶与脚下空间，固定机位中景。
2. **清除原图水印**：优先用**纯裁切把水印排除到画面外**，不要用 `delogo` 抹——在云海／渐变背景上 `delogo` 会留下明显矩形模糊块。
   - 实测：1024×1536 原图水印在右下角 `x>=868`，用 `crop=864:1536:0:0,scale=720:1280` 直接排除，画面无痕。
3. **统一比例**：优先与参考视频一致。竖屏短视频目标 9:16（720×1280）；2:3 图转 9:16 用裁切 + 缩放，不要拉伸变形。
4. **切分参考视频**：按动作分段表切成 N 段，每段单独作为对应生成段的动作参考，比整段传入更贴合时间区间。

```
ffmpeg -hide_banner -loglevel error -ss 0 -i "ref.mp4" -t 5 -c:v libx264 -crf 20 -pix_fmt yuv420p -an -y "refs/dance_01.mp4"
```

5. **单独提取原音轨**（后续混流用，别依赖生成侧保留音频）：

```
ffmpeg -hide_banner -loglevel error -i "ref.mp4" -vn -c:a aac -b:a 192k -y "original_audio.m4a"
```

## 5. 生成侧硬约束（实测，先验证再用）

| 约束 | 表现 | 处理 |
|---|---|---|
| 首帧与参考素材互斥 | `image` / `last_image` 与 `reference_images` / `reference_videos` / `reference_audios` 同时传会直接报错 | 把首帧放进 `reference_images`，角色参考与动作参考都用 reference 通道 |
| 音频不可禁用 | 模型强制生成音频，传 `enable_audio=false` 报错 | 不传该参数；最终用 ffmpeg 把生成音轨替换为原音轨 |
| 生成侧自动水印 | 每帧左上角叠加小标，实测范围 `x≈9..144 / y≈9..73`（720×1280 坐标） | 后期 `delogo=x=5:y=5:w=150:h=78`；区域偏小会残留，先放大 5 倍测准坐标 |
| 单次时长有限 | 通常一次约 5 秒 | 按分段表切 N 段生成再拼接；段数直接决定积分 |
| 动作精度 | **风格化迁移，非逐帧姿态复刻**：手势、上举、顶胯节奏保留，但会被美化成模型偏好的质感（如广袖古典舞、更夸张的衣发飘动） | 交付时如实说明；要求严格一致需改走 pose / motion transfer 路线 |
| 段间连续性 | 各段独立生成、共用同一首帧，靠原动作的循环性掩盖接缝；人物细节有轻微自然漂移 | 长编排舞蹈改用「上一段尾帧 → 下一段参考」，代价是外观可能逐段漂移 |
| `delogo` 边界 | 区域贴到画面边缘会报 `Logo area is outside of the frame` | `x>0`、`y>0` 且 `x+w < width-1`、`y+h < height-1` |

## 6. 积分与确认节点

- 图像生成约 **5–10 积分／张**；视频生成 **5 秒约 50–100 积分**，N 段按段数累加（20 秒约 200–400 积分）。
- **生成前必须告知总量并确认**：成品时长、歧义项（道具／角色呈现）、音乐来源（沿用原视频 / 生成氛围音 / 无声）。
- **先做第 1 段并抽帧验证**（人物、场景、动作三项都对齐），通过后再批量生成其余段。避免整批积分消耗完却发现首帧参考传错或角色不一致。
- 生成失败不擅自反复重试；参数报错按上表调整一次，仍失败就停下来告知用户。

## 7. 拼接与后期命令模板

统一每段规格（缩放 + 去生成水印 + 定帧率 + 去音轨 + 截到固定时长）：

```
ffmpeg -hide_banner -loglevel error -i "seg_01.mp4" -vf "scale=720:1280:flags=lanczos,delogo=x=5:y=5:w=150:h=78,fps=30" -t 5 -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p -an -y "norm_01.mp4"
```

顺序拼接（写一个 `concat.txt`：`file 'norm_01.mp4'` 逐行）：

```
ffmpeg -hide_banner -loglevel error -f concat -safe 0 -i "concat.txt" -c copy -y "merged_silent.mp4"
```

混入原音轨并按音频长度截断：

```
ffmpeg -hide_banner -loglevel error -i "merged_silent.mp4" -i "original_audio.m4a" -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -t 19.853 -movflags +faststart -y "final.mp4"
```

复核用两张图：

```
# 成品每 2 秒抽帧拼接触表，检查人物/场景一致性与段间跳变
ffmpeg -hide_banner -loglevel error -i "final.mp4" -vf "fps=0.5,scale=240:-2,tile=5x2:padding=4:margin=4:color=white" -frames:v 1 -y "preview_final.png"
# 左上角放大 5 倍，确认水印清除
ffmpeg -hide_banner -loglevel error -i "final.mp4" -vf "crop=220:120:0:0,scale=1100:600:flags=neighbor" -frames:v 1 -y "corner_zoom.png"
```

## 8. 如实交付

- 用接触表在 **8–10 个抽样时间点**确认角色、服装、背景、道具一致性，再看段间有无跳变；不要用首尾两帧下结论。
- 在 `operation-profile.md` 的「置信度与限制」写明：风格化迁移 vs 严格复刻、段间衔接策略、模型限制、水印处理方式、时长误差。
- `steps.json` 记录完整制作流程（取证 → 首帧 → 去水印 → 切段 → 分段生成 → 拼接混流），`replay-log.json` 逐步记实际结果，用 `verify` 出 `verification.json`。
- 完成率高也要列出保留的限制，不把「没有 pending_actions」等同于「和原视频一模一样」。

## 9. 安全边界

- 不覆盖原视频、原图与已生成的段；所有产物写入 `cases/` 与 `runs/` 新目录。
- 生成前确认积分与目标，生成后不自动发布、不自动分享。
- 涉及真人肖像、他人作品素材时，提示用户自行核对授权；不提供法律判断。
- 参考视频与取证帧仅本地处理；语音转录（若真有口述）需按主文档先取得确认。
