# 取证与对齐指南

本文件说明 `scripts/run.py extract` / `align` 产出什么、参数怎么选、哪些情况必须降级，以及看图时最容易犯的错。**取证与对齐前必读。**

## 1. 三层证据

| 层 | 产物 | 用途 | 局限 |
|---|---|---|---|
| 画面 | `frames/*.jpg`（固定间隔，带时间戳水印）、`scenes/*.jpg`（镜头切换）、`contact/*.png`（接触表） | 判断界面、控件、参数、状态变化 | 看不到鼠标轨迹与未展开的菜单；快速点击可能落在两帧之间 |
| 声音 | `audio.wav`（16k 单声道）、`transcript.*`、`timeline.json` | 把口述意图对应到画面动作，补出画面看不出的参数 | 转录会送出音轨，需先征得用户同意；口述常与实际操作错位几秒 |
| 元数据 | `evidence.json`、`probe` 输出 | 时长、分辨率、帧率、音轨／字幕有无、降级警告 | 不含任何语义信息 |

三层证据互相印证：画面定「做了什么」，声音定「为什么这么做」，元数据定「可信到什么程度」。

## 2. 抽帧参数选择

`--interval` 决定固定间隔帧密度，`--scene` 决定场景检测灵敏度。

| 教程类型 | `--interval` | `--scene` | 说明 |
|---|---|---|---|
| 菜单弹出、右键、拖拽、快速点击 | 1–2 | 0.2 | 操作窗口常短于 1 秒，宁可多抽帧 |
| 常规软件演示（默认） | 3 | 0.35 | 兼顾覆盖与图片量 |
| 讲解为主、操作稀疏 | 5–8 | 0.4 | 先用接触表定位操作密集段，再补抽 |
| 长教程（>30 分钟） | 5–10 或先裁剪 | 0.4 | `--max-frames` 默认 200，超限时脚本自动放宽间隔并写 warning |

`--width` 默认 960。参数面板文字小、需要读数值时可提到 1280 或 1600；接触表会缩到 320/480 宽，但单帧原图保留完整分辨率。

`--max-frames` 是保护性上限，不是目标帧数。自动放宽间隔属于降级，必须写进档案的置信度说明。

### 补抽密帧

接触表定位到关键区间后，对该段单独密抽（在取证目录内新建 `dense/`）：

```
ffmpeg -hide_banner -loglevel error -ss 12 -t 6 -i "D:/.../tutorial.mp4" -vf "fps=4,scale=1280:-2" -q:v 3 -strict unofficial -start_number 0 -y "D:/.../evidence/dense/d_%04d.jpg"
```

`-ss` 为起始秒、`-t` 为时长、`fps=4` 为每秒 4 帧。密抽帧**不进入** `evidence.json` 的时间轴，需在 `steps.json` 的 `evidence` 里按「原视频时间 = -ss + index/4」手算并标注为补抽帧。

对最关键的单帧，可放大局部再读数值：

```
ffmpeg -hide_banner -loglevel error -i "frame_0012.jpg" -vf "crop=400:200:700:320,scale=1200:600:flags=lanczos" -y "crop_0012.png"
```

## 3. 时间戳语义

- `frames/frame_0000.jpg` 对应 `time_sec = 0 * interval`，`frame_0001.jpg` 对应 `1 * interval`，依此类推；精确值以 `evidence.json` 的 `frames[].time_sec` 为准。
- 帧左上角的黄色水印显示 ffmpeg 输出流的 `pts`，格式 `HH:MM:SS.mmm`。视频 `start_time` 非 0 时，水印与真实时间存在偏移，偏移值记在 `extraction.start_time_offset_sec`，写步骤时间时加上它。
- `scenes/*.jpg` 的时间来自 `metadata=print` 的 `pts_time`，与 `lavfi.scene_score` 一并记在 `evidence.json` 的 `scene_frames` 里。
- `contact/*.png` 每张覆盖 `frame_range` 与 `time_range_sec`，按 3×2 / 4×3 / 4×5 网格随帧数自动选择；格内顺序为从左到右、从上到下。

## 4. 转录与对齐

### 转录结果落盘

调用语音转录能力时传入 `filePath`（指向 `evidence/audio.wav`）。**按实际返回格式选后缀**：

- 返回带 `segments` 等结构 → 存 `transcript.json`
- 返回 SRT/VTT 文本 → 存 `transcript.srt`
- 返回纯文本 → 存 `transcript.txt`

不得为了能对齐而手工编造时间戳。`align` 对纯文本走 `plain_text` 模式，把全文放进 `unaligned_text`，由 Agent 按顺序分配到步骤，并在 `warnings` 明确标注。

### align 支持的输入

| 后缀 | 解析方式 |
|---|---|
| `.srt` / `.vtt` | 解析 `-->` 时间行；支持 `说话人：内容` 前缀 |
| `.json` | 宽松识别 `segments` / `results` / `utterances` / `items` / `sentences` / `data` / `transcript` 等数组，字段名兼容 `start` / `begin` / `start_time` / `bg`、`end` / `finish` / `ed`、`text` / `content` / `sentence` 等；时间支持秒数、毫秒数、`HH:MM:SS` |
| `.txt` 及其他 | 纯文本模式，不做时间对齐 |

对齐采用**区间重叠**：片段与 `[当前帧时间, 下一帧时间)` 有交集即附到该帧的 `speech`。因此同一句话可能出现在相邻两帧，属正常现象，不是重复步骤。

`align` 会回写 `evidence.json` 的 `transcript` 与 `timeline` 字段。多次对齐（例如字幕 + 转录交叉校对）时给 `--out` 指定不同文件名，避免覆盖。

## 5. warnings 处置清单

| warning | 处置 |
|---|---|
| 自动放宽了抽帧间隔 | 档案注明实际间隔；对快速操作段补抽密帧 |
| 未找到字体 / 带水印抽帧失败 | 帧图无水印，靠 `evidence.json` 的 `time_sec` 定位；不影响流程 |
| 未检测到显著镜头切换 | 软件操作类教程常见，固定间隔帧已足够，无需处理 |
| 场景时间戳数量与帧数量不一致 | 以文件顺序为准，scene 帧时间标低置信度 |
| 接触表生成失败 | 直接逐张打开 `frames/*.jpg`，不要跳过看图 |
| 音轨提取失败 / 视频无音轨 | 走画面 + 内嵌字幕路线，参数置信度下调 |
| 内嵌字幕提取失败 | 让用户提供字幕文件，或依赖帧图 |
| 转录结果无时间戳 | 人工按叙述顺序分配到步骤 |
| 未解析出任何片段 | 检查文件是否为空或格式是否被误判，必要时改用 `.txt` |

## 6. 看图常见误判

1. **画面没变 ≠ 没操作**：拖拽、滚动、输入文本可能只在两帧之间发生，或只改变极小的区域。结合台词与前后帧差异判断。
2. **口述与操作错位**：讲解常提前或滞后 2–5 秒。以画面状态变化为步骤边界，台词只作意图佐证。
3. **结果展示被当成新步骤**：教程常回放「做完之后的效果」，该区间界面状态未变化，不生成步骤。
4. **鼠标指针不可见**：录屏常不捕获光标，无法区分点击与快捷键；把动作写成「触发 X 功能」，不要臆断具体点击坐标。
5. **参数被遮挡**：面板、水印、字幕遮住数值时标 `unverified` 并列入 `questions.md`，不要用常见默认值代替。
6. **倍速与剪跳**：注意时间轴突变（画面内容不连续），在档案里标注「疑似剪辑跳过」，该段步骤连续性降级。
7. **片头片尾与广告**：不属于操作流程，直接排除。
8. **相似界面混淆**：不同页面布局相近时，用标题栏、面包屑、左侧选中态辅助区分；仍无法区分则标低置信度。

## 7. 隐私与素材边界

- 关键帧若出现账号、手机号、密钥、订单、私人文件列表，先对图片打码再写入档案，或直接跳过该段并注明。
- 语音转录会把音轨送出本地，须在确认节点 0 明确告知用户；不允时改走纯画面路线。
- 联网下载只取教程公开视频，不绕过登录、付费或权限限制。
- 档案只保留必要关键帧，不整段转存教程视频。
